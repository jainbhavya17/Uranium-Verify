The source MVP was read as an implementation reference; only this nested redesign was modified. Its `.env`, operational database and private storage were not copied. Sample documents were generated afresh. Independent native processing tools were copied under ignored `var/tools`; their operational paths and definition freshness are documented in README.

## Design and implementation principles

A useful screen should answer: what is this record, what needs attention, where is the evidence, and what can I do next? Ordinary pages use that language. Technical provenance remains available under supporting-details disclosures when it helps an officer assess a result. External demonstrations, unknown states and unsupported methods stay explicit at their point of use.

## Restoration references

The restored portal content comes from the original Lovable project `../src/lib/data.ts` and archived earlier portal routes in `legacy/frontend`, exported without account credentials into `config/portal-samples.json`. The separate Uranium project's generic interface was not used for the restored overview/case layouts. Its previously integrated backend adapters remain behind the current approved visual system.

The original university asset is `public/campus.svg`. The user-supplied mandala is preserved as `public/mandala.png` and coloured through CSS, with decorative accessibility semantics.

UX4G references: [Application submission](https://www.ux4g.gov.in/patterns/application-submission) and [Accessibility](https://www.ux4g.gov.in/foundations/accessibility). Applied clear next actions, saved progress, named uploads, textual status indicators, keyboard controls and reduced motion. This is not a UX4G certification.

The restored supporting-document package is explicitly a portal reference checklist. Affidavit references link to the APH annexures; the complete category-specific regulatory interpretation still needs official review before production use.
